## 1. สรุปสำหรับผู้บริหาร

Core loop ของ GDD **ทำครบและเล่นจบได้จริง** ตั้งแต่เมนู → จัดร้าน → รับออเดอร์ → ดูแล → ส่งคืน → จบวัน → เลือกรางวัล/ร้านค้า → จบ run พร้อมหน้าสรุป

ส่วนที่ยังขาดคือ**ระบบชั้นที่สองของ GDD**: Reputation, เฟสรอรับคืนของเจ้าของ, โซนตามชนิดสัตว์ และระบบผังสุ่ม
ส่วนที่ตั้งใจ **ไม่ทำ** และขอแก้เอกสารแทน: HP System, Permadeath ทันที, XP/ศูนย์บัญชาการ

| หมวดของ GDD | ความคืบหน้า |
|---|---|
| Core Gameplay Loop | ✅ 100% |
| Pet Needs | ✅ 100% (ปรับเป็น checklist ไม่เรียงลำดับ) |
| Stress / สัตว์หนี–ไล่จับ | ✅ 90% (ขาดแต่โซนที่ส่งผลต่อโอกาสหนี) |
| Owner Patience 3 เฟส | ⚠️ 2 จาก 3 เฟส |
| เศรษฐกิจ (เงิน / Blueprint) | ✅ 100% · ❌ Reputation ยังไม่มี |
| Level & World Design | ⚠️ ผังคงที่ 1 แบบ · ยังไม่มีผังสุ่ม/โซน |
| Roguelite Structure | ⚠️ 3 วัน + แพ้/ชนะ ✅ · meta-progression ตัดออก |
| ตัวละคร & สัตว์ | ⚠️ 3 ชนิด (ไม่ตรงรายชื่อใน GDD) |

## 4. ขอแก้ GDD 3 ข้อ (พร้อมเหตุผล)

> ส่วนนี้สำคัญต่อการนำเสนอ — การเขียนเหตุผลกำกับการตัด มีน้ำหนักกว่าการพยายามทำครบทุกข้อแล้วไม่เสร็จ

| GDD เขียนว่า | ของจริง | เหตุผล |
|---|---|---|
| **HP System** — ป่วย → ค่ารักษา → HP 0 จบ run | ไม่ทำ | ซ้อนทับกับมิเตอร์ความอดทน + ระบบสัตว์หนี เป็นนาฬิกาลงโทษอันที่สาม ผู้เล่นมองไม่ทันทั้งสามอัน |
| **Permadeath ทันที** เมื่อเจ้าของ 1 รายหมดอดทน | ร้องเรียนครบ 5 | run ละ 3 วัน (~12 นาที) ถ้าพลาดครั้งเดียวจบเลย คนเทสจะเลิกก่อนเห็นระบบอื่น |
| **XP + ศูนย์บัญชาการ** | หน้าสรุป run | run สั้น + ของให้ปลดล็อกมีแค่ ~8 ชิ้น meta-progression ไม่มีเวลาออกดอกผล (อ้างอิง: PlateUp ใช้ HQ กับ run 60–90 นาที) |

**ค้างให้ตัดสินใจ:** GDD ระบุสัตว์ กระต่าย/แฮมสเตอร์ แต่ของจริงมีหมู → เลือกทางเดียว (แก้ GDD เป็นหมู หรือปั้นกระต่ายเพิ่ม) ไม่ควรปล่อยให้ขัดกัน

## 5. แผนพัฒนาต่อ

### ลำดับที่แนะนำ

| # | งาน | เวลา | ที่มา |
|---|---|---|---|
| 0 | **เทส + commit ก้าว 4 (ตู้สินค้า)** | ครึ่งวัน | ค้างอยู่ |
| 1 | **Reputation แยกจากเงิน** | 1 วัน | GDD |
| 2 | **เฟสรอรับคืนของเจ้าของ** | 1–2 วัน | GDD |
| 3 | **ระบบผังร้าน + โซนตามชนิดสัตว์** | 6–9 วัน | GDD + System[New].pdf |
| 4 | **บุคลิกสัตว์ + Audio Mixer** | 1.5 วัน | GDD + บทเรียนบทที่ 11 |
| 5 | **งานศิลป์ + bugfix** | ทำคู่ขนาน | — |

**เหตุผลที่สลับ 1 กับ 2 มาก่อนระบบผัง:** ทั้งคู่ถูก เร็ว และอยู่ใน GDD อยู่แล้ว ถ้าเวลาหมดจริง เกมที่มี 2 ระบบนี้ยังตรง GDD มากกว่าเกมที่มีระบบวางผังแต่ loop ตื้น

### รายละเอียดงานที่ยังไม่เริ่ม

**1. Reputation**
- ส่งคืนครบทุกขั้นตอน +1 · ไม่ครบ −1 · ร้องเรียน −2 · ส่งสินค้าที่ลูกค้าสั่ง +1
- Reputation กำหนดจำนวนลูกค้าของวันถัดไป (สูง = คนเยอะ = เงินเยอะแต่ยากขึ้น)
- ได้แกนตัดสินใจที่สอง: รีบคืนทั้งที่ไม่ครบเพื่อเคลียร์คิว vs ทำให้ครบ

**2. เฟสรอรับคืน**
- สัตว์ครบทุกขั้นตอน → เจ้าของลุกจากที่นั่งมายืนรอที่เคาน์เตอร์ พร้อมมิเตอร์ ~20 วิ
- ส่งคืนไม่ทัน = ร้องเรียน
- ใช้ของเดิมเกือบหมด (state ลูกค้า + มิเตอร์ + จุดคืน)

**3. ระบบผังร้าน (ก้าวที่ 5)**

| ชิ้น | เวลา | สถานะ |
|---|---|---|
| 5.0 `TileGrid.blockedCells` | — | ✅ เสร็จแล้ว |
| 5.1 ตัวตรวจผัง (flood fill) "เดินถึงทุกสถานีไหม" | 1 วัน | |
| 5.2 `ShopBlueprint` (ScriptableObject) | 1 วัน | |
| 5.3 โหมด preset 3 ผัง (ทางเดียว / เกาะกลาง / ตัว L) | 2 วัน | |
| 5.4 โหมด generate จากพารามิเตอร์ | 3–4 วัน | ตัดได้ถ้าเวลาไม่พอ |
| 5.5 ห้องซ้อม (ลูกค้าจำลอง) | 1 วัน | |
| 5.6 **โซนตามชนิดสัตว์** (เงียบ/เล่น) | 2 วัน | GDD — ทำให้ผังมีความหมายจริง |

**4. บุคลิกสัตว์** — เพิ่ม trait ใน `PetSpecies`: ขี้ตกใจ (หนีไวขึ้น 40%) · ติดคน (อยู่ในมือแล้วมิเตอร์ลดช้าลง)

## 8. ความเสี่ยงและลำดับการตัด

| ความเสี่ยง | ทางรับมือ |
