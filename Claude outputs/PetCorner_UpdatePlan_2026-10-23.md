## 1. สถานะปัจจุบัน

### เล่นได้แล้วตั้งแต่ต้นจนจบ
เมนูหลัก → เลือกสัตว์ → จัดร้าน → เปิดร้าน → ลูกค้าเข้า → รับออเดอร์ → ดูแลตามขั้นตอน → ส่งคืน → จบวัน → เลือกรางวัล → ร้านค้า → วันถัดไป → จบ run (ชนะ/แพ้) → เล่นใหม่

## 2. แผนงานที่เหลือ

### ก้าวที่ 4 — ตู้สินค้า + ลูกค้าขอของ · 3–4 วัน ⬅️ ต่อไป

เพิ่ม**ทางเลือก**ให้ผู้เล่น ไม่ใช่เพิ่มภาระ: จะรีบรับออเดอร์ถัดไป หรือแวะหยิบของไปขายเอาเงินเพิ่ม

- `GoodsShelf` เป็นสถานีบนกริด (ยก/ย้ายได้เหมือนสถานีอื่น) เก็บสินค้า 3–4 ชนิด
- `Customer.DemandedGood` สุ่มตอนรับออเดอร์ · ส่งสัตว์คืนแล้วลูกค้าขอของ → หยิบมาให้ → เงินเพิ่ม 30–50%
- ลูกค้ารอของตามเวลาที่เหลือของมิเตอร์เดิม ไม่ต้องมีมิเตอร์ใหม่
- อ้างอิง: Extra Items ของ PlateUp (ลูกค้าขอของเพิ่มระหว่างกิน)

**เสร็จแล้วได้อะไร:** ร้านมีจุดเดินเพิ่มอีกจุด = ผังร้านเริ่มมีความหมายจริง ก่อนจะไปทำระบบออกแบบผัง

### งานแทรก — หน้าสรุปท้าย run · 1–2 ชม.

ของชิ้นเดียวจากระบบ Headquarters ที่คุ้มค่าทำ ทำพร้อมก้าวที่ 4 ได้เลย

> ไปถึงวันที่ 2/3 · ออเดอร์สำเร็จ 7 · ทิป 24 · สัตว์หนี 3 จับคืนได้ 2 · การ์ดที่เลือก … · **แพ้เพราะ: ลูกค้าหมดความอดทนที่เคาน์เตอร์ 3 ครั้ง**

บรรทัดสุดท้ายสำคัญที่สุด — ทำให้คนอยากกดเล่นใหม่ และเก็บข้อมูล balance จากคนเทสได้ฟรีทุกรอบ

### ก้าวที่ 5 — ระบบออกแบบผังร้าน · 8–10 วัน

| ชิ้น | เวลา | หมายเหตุ |
|---|---|---|
| 5.0 `TileGrid.blockedCells` | 2–3 ชม. | **ต้องมาก่อน** — ตอนนี้กริดเป็นสี่เหลี่ยมเต็มผืน ห้องตัว L/มีเสาจะวางของทะลุกำแพงได้ |
| 5.1 ตัวตรวจผัง (flood fill) | 1 วัน | "เดินถึงทุกสถานีไหม" ใช้ซ้ำทั้งในการ generate และตอนผู้เล่นวางเอง |
| 5.2 `ShopBlueprint` (ScriptableObject) | 1 วัน | เก็บผังเป็นข้อมูล: ขนาด กำแพง ประตู ช่องห้าม |
| 5.3 โหมด preset (3 ผัง) | 2 วัน | A ทางเดียว · B เกาะกลาง · C ตัว L |
| 5.4 โหมด generate จากพารามิเตอร์ | 3–4 วัน | กรอกขนาด/จำนวนประตู/ห้อง → สร้างผัง + ตรวจสมดุล |
| 5.5 ห้องซ้อม (ลูกค้าจำลอง) | 1 วัน | ทดสอบผังก่อนเปิดร้าน — จำเป็นขึ้นมากเมื่อผู้เล่นออกแบบผังเองได้ |

**นี่คือจุดขายที่ต่างจากต้นแบบจริง** — PlateUp สุ่มผังให้ ผู้เล่นออกแบบเองไม่ได้ (ต้องใช้ mod)

### งานศิลป์ที่ค้าง (ทำคู่ขนานได้ตลอด)

โมเดลที่ยังไม่มี: **Rest** (มี cage แล้วแต่ยังไม่ import) · **Play** · **Groom** · **ReturnZone** · **HoldingTable** · **Parcel** · **โต๊ะห้องรอ** (ตอนนี้เป็นแท่นสร้างอัตโนมัติ)

## 3. ตารางเวลาโดยประมาณ

```
ก้าว 4 + หน้าสรุป run   ~4 วัน    → loop มีความลึกพอให้เทสจริง
ก้าว 5.0–5.3           ~5 วัน    → ผัง preset เล่นได้ 3 แบบ
ก้าว 5.4–5.5           ~5 วัน    → generate + ห้องซ้อม
งานศิลป์ + bugfix       ~5 วัน    → ทำคู่ขนาน
                      รวม ~14–19 วันทำงาน
```

**จุดตัดสินใจ:** ถ้าเหลือเวลาไม่ถึง 10 วัน ให้ตัด 5.4 (generate) ออกก่อน เหลือ preset อย่างเดียว — ผู้เล่นยังรู้สึกว่า "เลือกผังร้านได้" ครบ

## 4. สิ่งที่ตัดออกแล้ว (ยืนยัน)

| ตัด | เหตุผล |
|---|---|
| ระบบจ้างพนักงาน / โหมดผู้จัดการ | PlateUp ไม่มี NPC staff เลย — ไม่มีต้นแบบ ต้องทำ NavMesh + task queue เอง และเปลี่ยนเกมเป็นคนละแนว |
| Multiplayer | ต้องรื้อ input/state ทุกระบบ รอทุกอย่างนิ่งก่อน |
| สร้างผังแบบคลิกลากอิสระ | แพงสุดในกลุ่ม blueprint · preset + generate ให้ความรู้สึกครบแล้ว |
| ระบบ Headquarters เต็มรูป | run ละ 10–15 นาที มีของให้ปลดล็อกแค่ 8 ชิ้น — meta-progression ไม่มีเวลาออกดอกผล เก็บแค่หน้าสรุป run |
| ตัวจับเวลาต่อวัน | ต้นแบบยืนยัน: วันจบเมื่อเสิร์ฟครบ ไม่ใช่หมดเวลา |
| ขยายร้านแบบอิสระ | ใช้ preset 3 ขนาดแทน ได้ผลเท่ากันด้วยเวลา 1/5 |

## 6. เกณฑ์ตัดสินใจระหว่างทาง

- **หลังก้าว 4 ให้หยุดเล่นเองให้จบ 1 run** ก่อนเริ่มก้าว 5 — ถ้ายังไม่สนุก ปัญหาอยู่ที่ตัวเลข/จังหวะ ไม่ใช่ที่ระบบที่ยังไม่ได้ทำ
